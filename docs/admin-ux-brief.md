# אפיון מסך אדמין — momoEVENT  
**מסמך לצוות UX/UI · מצב קיים (As-Is) · ללא שינוי קוד**

מטרת המסמך: לתאר את הנראות, המבנה והפונקציות של ממשק האדמין הקיים, כדי לאפשר תכנון ויזואליזציה חדשה בלי לאבד יכולות.

---

## 1. הקשר מוצר

| פריט | פירוט |
|------|--------|
| מוצר | momoEVENT — ניהול הזמנות ואירועים (RTL / עברית) |
| מסך | מרכז ניהול מערכת לאדמין (`/admin`) |
| כניסה | `/admin/login` |
| קהל יעד | מנהל מערכת (SYSTEM_ADMIN) — לא מנהל אירוע ולא סוכן |
| שפה וכיוון | עברית, RTL; שדות טכניים (טלפון, username, URL) ב־LTR |

**תפקידים קשורים (לא חלק ממסך זה):**
- **מנהל אירוע** (`/manager`) — פותח ומנהל זוגות/לקוחות שלו בלבד; בלי עסקאות, קופונים, לידים וחשבונות מנהלים.
- **סוכן** (`/agent`) — סבבי טלפון / RSVP.

## 2. כניסה והרשאות

### מסך התחברות
- כותרת: **כניסת מנהל**

- קישור: **חזרה לדף הבית**

### אחרי התחברות
- בדיקת סשן; במצב המתנה: **בודק הרשאות…**
- התנתקות ממסך האדמין → חזרה ל־`/admin/login`

## 3. מבנה העמוד הנוכחי (סדר ויזואלי מלמעלה למטה)

המסך הוא **עמוד ארוך אחד בגלילה** — ללא תפריט צד וללא טאבים.

1. **כותרת עמוד** — «מרכז ניהול אירועים» + משפט הסבר
2. **סרגל פעולות** — «לקוח חדש» · «התנתקות»
3. **הודעות מערכת** (שגיאה / הצלחה גלובלית)
4. **כרטיסי מדדים** (3)
5. **לקוחות לפי סוכן** (מוצג רק אם יש נתונים)
6. **מנהלי אירוע** — ניהול חשבונות שותפים ל־`/manager`
7. **פניות מדף הנחיתה** — לידים
8. **אזור עבודה ראשי בשתי עמודות:**
   - ימין/רשימה: **לקוחות פעילים**
   - שמאל/פרטים: **פרטי לקוח** (תלוי בבחירה)
9. **מודאל** — אשף יצירה/עריכת לקוח (מעל העמוד)
10. **כרטיס הצלחה אחרי יצירה** — קישורי שיתוף והעתקה

### הערת ארכיטקטורה ל־UX
השם «אשף» קיים במוצר, אבל ה־UX הנוכחי הוא **טופס ארוך אחד במודאל**, לא שלבים (steps).  
ריבוי דומיינים תפעוליים בעמוד אחד (מנהלים, לידים, לקוחות, עסקה, וואטסאפ) הוא נקודת כאב מרכזית לרידיזיין.

## 6. מנהלי אירוע

**מטרה:** האדמין פותח ומנהל חשבונות התחברות לממשק `/manager`.

### יצירה
- שם לתצוגה
- שם משתמש
- סיסמה (מוצגת בטקסט — לתמיכה)
- CTA: **פתיחת מנהל אירוע**

### רשימת חשבונות
לכל מנהל:
- שם תצוגה + username
- סטטוס: פעיל / מושבת
- סיסמה נוכחית (לתמיכה)
- עדכון סיסמה
- השבתה / הפעלה

### Bootstrap מהשרת (env)
אם מוגדרים `EVENT_MANAGER_USERNAME` / `PASSWORD` — מוצגת הערה שהחשבון קיים מהשרת והסיסמה לא מנוהלת במסך.

## 8. רשימת לקוחות פעילים

**מטרה:** בחירת לקוח לעבודה בלוח הפרטים.

### חיפוש
שדה מהיר: שם, תאריך, טלפון, משתמש, מקום, סוג אירוע, סוכן…

### שורת לקוח
- כותרת: שם האירוע / בני הזוג / מארגן וכו׳ (לפי סוג אירוע)
- שורה משנית: תאריך אירוע (או «ללא תאריך אירוע»)
- מצב נבחר מודגש ויזואלית

### פעולות בשורה
- לחיצה → בחירה
- עריכה (עיפרון) — ללקוחות IL בלבד (לקוחות US ללא עריכה ממסך זה)
- מחיקה — עם אישור: מחיקת הלקוח וכל נתוני האירוע

### מצבים
- טעינה / שגיאה / ריק / אין תוצאות לחיפוש

## 9. פרטי לקוח נבחר

מוצג רק אחרי בחירה מהרשימה. ריק: «בחרו לקוח מהרשימה להצגת פרטים».

### 9.1 סיכום אירוע
- סוג אירוע · תאריך · מיקום (שם מתחם)

### 9.2 פרטי גישה וקישורים
| שדה | פעולה טיפוסית |
|------|----------------|
| נפתח ע״י סוכן | תצוגה בלבד |
| מספר הזמנה באטסי | העתקה (בעיקר US) |
| כתובת מייל | העתקה |
| תאריך יצירה | תצוגה |
| טלפון איש קשר | העתקה |
| שם משתמש | העתקה |
| סיסמה | תצוגה לתמיכה + העתקה |
| קישור הזמנה (עמוד אורחים) | פתיחה + העתקה |
| קישור דשבורד לקוח | פתיחה + העתקה |

אופציונלי: תצוגת תמונת קאבר של האירוע.

### 9.3 מכסת וואטסאפ (קופונים)
- רשימת קופונים קיימים: קוד · יתרה / סה״כ · סטטוס (פעיל / מוצה / לא פעיל)
- הוספת קופון חדש: שם קוד + מכסת הודעות
- CTA: **הוספת קופון נוסף ללקוח**
- כלל מוצר: קופונים מצטברים — חדש לא דורס קיים

### 9.4 פרטי עסקה ושיווק (אדמין בלבד)
זהו אזור ה־«מנהל מערכת» העסקי — לא זמין למנהל אירוע.

**סוג חבילה:** התאמה אישית · דיגיטל · VIP — 2 סבבים · VIP — 4 סבבים

**פיצ׳רים וסבבים:**
- בחירת **תבנית וואטסאפ להזמנה** (5 אפשרויות — ראו סעיף 10)
- סבבי וואטסאפ (1–2)
- סבבי שיחות טלפון (1–4)
- תזכורת ביום האירוע
- שליחת מספר שולחן ביום האירוע
- הודעת תודה

**שדות כספיים/שיווק:**
- מקור הגעה / שיווק
- סכום ששולם · אמצעי תשלום (ביט / פייבוקס / העברה / מזומן / אחר)
- פירוט חבילה · מחיר חבילה · עלות ספק
- קוד קופון
- הערות סוכן · הערות מנהל

CTA: **שמירת פרטי עסקה**

### 9.5 שליחת הרשאות בוואטסאפ
- שליחת תבנית Quick Reply לקבלת פרטי גישה לטלפון איש הקשר
- CTA: **שלח הרשאות** (מושבת בלי טלפון)

### 9.6 הודעה מוכנה ללקוח
- טקסט מוכן עם username, סיסמה, קישורי הזמנה ודשבורד
- **העתק הודעה ללקוח**

### 9.7 דוח כשלים בוואטסאפ
- סינון להודעות שנכשלו / לא נמסרו
- רענון מ־Twilio · ייצוא לאקסל
- חיפוש לפי שם/טלפון
- טבלה: שם מוזמן · טלפון · קוד שגיאה · סיבה · תאריך ושעה

## 10. אשף יצירה / עריכת לקוח (מודאל)

### מצבים
| מצב | כותרת | שמירה |
|-----|--------|--------|
| יצירה | אשף יצירת לקוח חדש | יוצר לקוח + אופציונלית תמונה |
| עריכה | עריכת לקוח | מעדכן פרטים + תמונה |

סגירה: X / ביטול.

### בלוק חשבון
- שם משתמש (חובה)
- סיסמה (חובה ביצירה; בעריכה אופציונלית — ריק = ללא שינוי)
- טלפון הכלה / איש קשר (חובה ביצירה)

### בלוק פרטי אירוע
שדות משתנים לפי **סוג אירוע**:

| סוג | שדות ייחודיים עיקריים |
|-----|------------------------|
| חתונה / חינה / אירוסין | שם חתן, שם כלה, קבלת פנים + שעת טקס/חופה |
| ברית | הורים, תאריך עברי אופציונלי |
| בר/בת מצווה | שם כלת/בר המצווה + הורים |
| כנס | מארגן, שם במה/מותג, סושיאל, כתובת, חניה, קישור אתר |

משותף לרוב הסוגים (לא כנס): מתחם · עיר · רחוב ומספר · תאריך · שעה.

אופציות נוספות:
- תיאום הסעות/טרמפים (+ קישור לקבוצת וואטסאפ)
- שאלה על רגישויות מזון / אלרגיות
- מכסת סבבי שיחה טלפוניים (ללא / 1–4)
- תבנית וואטסאפ להזמנה
- העלאת תמונת אירוע (עד 8MB) / הסרה

### תבניות וואטסאפ להזמנה (5)
1. **מלל רגיל (ללא כרטיס)**
2. **כפתורים מהירים (ללא תמונה)**
3. **כרטיס מלא** (קישור + 3 כפתורים)
4. **כרטיס מהיר** (3 כפתורים)
5. **כרטיס הפניה** (כפתור קישור יחיד)

### אחרי יצירה מוצלחת
- בחירת הלקוח החדש ברשימה
- כרטיס «הכול מוכן» עם:
  - פרטי גישה
  - העתקת הודעה ללקוח
  - העתקת הודעת שיתוף לאורחים (סוג אירוע, תאריך, שעות, מקום, קישור RSVP)
- הודעות על שליחת וואטסאפ ברוכים־הבאים (אם נשלח / דולג / נכשל)

## 14. נקודות כאב מוצר (לצוות UX — לא דרישות פיתוח)

1. **עמוד אחד לכל הדומיינים** — עומס קוגניטיבי גבוה; מומלץ לשקול IA: דשבורד / לקוחות / לידים / מנהלים / הגדרות.
2. **«אשף» שאינו מדורג** — טופס ארוך; מומלץ steps או progressive disclosure לפי סוג אירוע.
3. **סיסמאות ב־plaintext** — דפוס תמיכה מכוון; לשמור נגישות לתמיכה גם אם משתנה הצגה.
4. **מודאל + גלילת עמוד + כרטיס הצלחה** — שלושה מצבי UI מתחרים; כדאי לאחד מסע יצירה.
5. **אישור מחיקה ב־`window.confirm`** — חוויית מערכת גולמית; מועמד למודאל מותאם.
6. **לקוחות US** — שדות Etsy/מייל קיימים; עריכה מוסתרת — צריך להחליט אם יש מסלול US נפרד.
